# 日本語PPG・トークン編集・FB・音声評価の実行手順

[概要](../README.md) / [実験一覧と結果](../reports/experiments.md) / [JSUTパイプライン](jsut-pipeline.md)

コマンドはリポジトリのルートで実行する。既存の出力は上書きしないため、再実行には新しい`--output-dir`を指定する。

## 日本語PPGの抽出・比較（40 ms・128コード）

既存の試聴5発話について、元音声・オリジナル調音軌道からの合成・トークン再構成軌道からの
合成の3種類から、同じ日本語モデルでPPGを生成する。

```sh
bash scripts/extract_jsut_ppg.sh \
    --run-dir outputs/jsut_window_sweep/window_040ms \
    --output-dir outputs/jsut_ppg_40ms128 --limit 5
```

`--device auto`（既定）、`cpu`、`cuda`、`cuda:N` に対応する。
環境は既存の `setup_resynthesis.sh` と共通で、追加パッケージの導入は不要。
初回は公開モデルを Hugging Face のキャッシュへ取得する。
入力はrunの `audio_comparison/manifest.json` に記録されたテスト音声で、再合成は行わない。
既存の出力は上書きしないので、再実行時には新しい `--output-dir` を指定する。

モデルは [taisa1/ppgs_ja](https://github.com/taisa1/ppgs_ja) の日本語35音素モデル。
`taisa1/ppgs-ja/mel_ja.pt` のrevision
`c77bee7a8110b12d1d4fc10989b457e185e2a3b3` と、ソースのcommit
`d2dac95fd6f40ba0f2708b4a3561c4912e2490d1` を固定する。
必要なモデルと前処理をPyTorchアダプターとして実装し、MIT表記と変更内容を
[third_party/ppgs_ja](../third_party/ppgs_ja/README.md) に記載した。
英語モデルや英語音素の類似度行列は使用しない。

音声を16 kHz・モノラルへ変換し、同じSTFT・log-Mel条件で推論する。
音量の個別正規化は行わない。出力は無音 `<silent>` を含む35音素の事後確率で、
100 Hz（10 ms刻み）。STFTは1024サンプル、hop 160、前後432サンプルのreflect paddingを用い、
先頭フレームの中心時刻は5 msとする。PPGの時間方向の平滑化・補間・離散化は行わない。
元実装のFP16丸めをスペクトル振幅とlog-Melに適用し、Mel行列積とTransformerはFP32で計算する。
モデルは非因果的で、1発話全体を処理する。上限は5000 PPGフレーム（約50秒）。

出力は `outputs/jsut_ppg_40ms128/<subset>/<発話ID>/` に保存する。

| 保存物 | 内容 |
|---|---|
| `original.npz` | 元音声のPPG |
| `original_ema.npz` | オリジナル軌道からの合成音声のPPG |
| `reconstructed_ema.npz` | トークン再構成軌道からの合成音声のPPG |
| `comparisons.npz` | 3組それぞれの共通フレーム時刻・JS divergence |
| `ppg_comparison.png` | 同じ音素順・確率スケールの3ヒートマップと、時刻別JS divergence |
| 同名のWAV | 入力音声の変更しないコピー |

各PPG NPZには `ppg: (T,35)` float32、`time: (T,)`、`phonemes`、`frame_rate`、
元音声のサンプリング周波数・長さ・チャンネル数、モデル版とチェックサムを格納する。
読み込みには `np.load(path, allow_pickle=False)` を使用できる。

全体の `index.html` で音声と図を確認でき、`summary.csv`・`summary.json` に発話ごとの
平均・中央値・95%点・最大JS divergenceを保存する。全体平均は比較フレーム数による重み付き平均。
JS divergenceは自然対数を使う通常の定義（0〜log(2) nats）で、3組
「元音声↔通常合成」「元音声↔トークン再構成合成」「通常合成↔トークン再構成合成」を比較する。
音声長が異なる場合は共通する実時間フレームだけを使い、時間伸縮やDTWは適用しない。
PPGはモデルの推定分布であり、正解音素ラベルや発音の正しさそのものとは区別する。
`manifest.json` に入力音声・VQモデル・PPGモデルの版、SHA-256、前処理、処理結果を記録する。

## PPGを目標にしたトークン局所探索

40 ms・128コード・50 Hzのトークン列から、1トークンの置換を繰り返して元音声の日本語PPGへ近づける。
既定では差の大きかった試聴3発話（0053・0050・0066）を対象にする。

```sh
bash scripts/local_jsut_ppg_search.sh \
    --output-dir outputs/jsut_ppg_local_search \
    --passes 2 --positions 24 --neighbors 12 --global-candidates 4 --batch-size 4
```

各パスでPPG差の大きい24位置を選び、各位置につき、デコードした標準化軌道が近い12コードと、
コードブックを広くカバーする追加4コードを評価する。候補は学習データで使用されたコードに限定する。
学習トークンが未保存の場合は、固定したVQモデルで学習軌道を再エンコードして使用数だけを集計し、入力ファイルは変更しない。
候補は発話全体を合成・PPG推論し、共通する絶対時刻での全フレーム平均JS divergenceを評価する。
改善候補を単独バッチで再検証し、`--min-improvement`（既定1e-5）より大きく改善した置換だけを採用する。
遷移確率・編集数・軌道の正則化は使用しない。F0・音量・話者埋め込み・合成ゲイン・系列長を固定する。
予算を制限した貪欲探索なので、全位置・全コードに関する局所最適性は保証しない。

`--utterances BASIC5000_0053` で対象を指定できる。`--neighbors 127 --global-candidates 0` では
各選択位置で利用可能な他コードをすべて評価する。再実行時には新しい `--output-dir` を指定する。
GPUを推奨する。合成器は既存のSPARC多言語モデルのgeneratorのみを読み込み、保存済みの合成条件を再利用する。
合成モデルrevisionは `2e6a07d4b35022d4366a2896a6293fe16aaed78a` に固定し、
編集前の音声が保存済みの音声を再現することを確認する。
候補は固定ゲインを適用してPCM16へ量子化してからPPGを評価する。PPGの位置合わせや時間伸縮は行わない。

出力の `index.html` で元音声・元軌道合成・トークン編集前・編集後を試聴できる。
各発話の `result.npz` には編集前後のトークン・調音軌道・PPG・JS列・固定した合成条件を保存する。
`trace.jsonl` は評価した位置・候補数・採否・採用後の損失を記録し、`summary.csv` と
`manifest.json` は改善量・編集数・評価回数・モデルのチェックサムを記録する。
最終WAVからPPGを再抽出し、保存音声でも採用時の損失を再現することを検証する。
PPGの一致が聴感や発音の改善を保証するわけではないため、編集前後を聴き比べる。

## 遷移確率のソフト制約付き局所探索

平均PPG JSに、系列全体の平均遷移負対数確率を加えて最小化できる。

```sh
# 同じ3発話・同じ探索予算で λ=0 / 0.01 / 0.03 / 0.1 を比較
bash scripts/sweep_ppg_transition.sh \
    --output-dir outputs/jsut_ppg_soft_transition

# 1条件を実行する場合
bash scripts/local_jsut_ppg_search.sh \
    --output-dir outputs/jsut_ppg_local_lambda003 \
    --transition-weight 0.03 --transition-alpha 1
```

目的関数は `mean_JS + λ * mean(-log A[z_i, z_(i+1)])`。
1トークンを変更した候補について、前後の両遷移を反映した系列全体のNLLを評価する。
合計損失が改善する候補だけを単独バッチで再検証して採用し、PPG差だけの単調減少は要求しない。
`λ=0` は従来の制約なし探索と同じ採否になる。
探索位置の選択は従来どおりPPG差に基づき、候補生成・24位置×2パス・16候補も同じにする。
各λは編集前のトークン列から独立に開始する。

遷移確率は学習データだけから推定する一次マルコフモデルで、自己遷移を含み、発話境界をまたがない。
`A[a,b] = (C[a,b]+α)/(sum_b C[a,b]+128α)` により未観測遷移にも正の確率を与える。
比較スクリプトのαは既存実装の既定値1に固定しており、検証データで最適化した値ではない。
検証・テスト発話は遷移モデルの推定に使わない。学習系列は一度だけ集計し、モデルも条件間で共有する。
元のVQ・合成・PPGモデルと、既存のトークン・音声ファイルは更新しない。

比較出力の `index.html` で条件間の音声・PPG差・遷移NLL・未観測遷移率・自己遷移率を確認できる。
`summary.csv` は発話別、`aggregates.csv` は条件別の集計。
全体JSはPPGフレーム数、遷移指標は遷移数で重み付けする。
各条件の `transitions.npz` に学習遷移カウント・確率・平滑化係数・VQチェックサムを保存する。
発話別CSVには連続する同一コードの平均長・最大長も記録し、`trace.jsonl` には
JS・遷移NLL・合計損失を別々に記録する。異なるλの合計損失同士を直接比較しない。
遷移NLLが低いことが聴感の改善を保証するわけではないため、PPG差と音声を併せて評価する。

## 音声を100 msずつ確定する逐次PPG探索の比較

```sh
bash scripts/compare_sequential_ppg.sh \
    --output-dir outputs/jsut_ppg_sequential
```

既存の3発話について、探索範囲200・400・800 msのそれぞれで、逐次無編集・PPG補正なし・PPG補正ありを比較する。
λ=0.03、確定幅100 ms。各ステップで探索範囲内の差が大きい5位置×2パス、各16コード候補を評価する。
未来の未確定部分は次ステップに引き継いで再編集できるが、確定したトークンと音声サンプルは変更しない。
候補の合成・PPG予測には、現在位置から探索範囲の末尾までの入力しか使わない。
損失は未確定の探索区間の平均JS＋0.03×平均遷移NLL。遷移NLLには確定済み末尾からの流入遷移も含める。
1トークンずつの改善候補を単独バッチで再検証する。区間先頭10 msは前回予測の未出力部分とクロスフェードする。
候補評価にも同じクロスフェードと、実際に確定済みの音声サンプルを使用する。

PPGの観測は出力済み音声だけから計算し、100 ms遅延で確定・保持する。末尾100 msはEOSで確定する。
補正ありでは、確定した観測PPGとその音声を出力する前の予測PPGを比較し、
新しく観測可能になった区間の音素別確率平均のlog比を求める（floorではなく分子分母に0.001を加算）。
log比を±1に制限し、更新率0.25の指数移動平均で音素別バイアスを更新する。
次の探索では `softmax(log(predicted_ppg)+0.5*bias)` を目標PPGと比較する。
補正なしは同じ予測器・確定済み波形を文脈に使い、バイアスをゼロに固定する。
この実験のFBは予測と観測のずれの補正であり、過去の目標誤差を将来の別音素で埋め合わせる方式ではない。

既存の非因果PPGモデルを有限の観測遅延で使用する近似なので、観測値は発話全体のPPGとは異なる。
主評価は、確定して結合した実際の出力WAV全体から再抽出した、補正を加えていないPPGのJSとする。
固定遅延で凍結したPPGのJS、遷移NLL、編集数、区間境界のサンプル差分、候補評価回数、処理時間も保存する。
境界のサンプル差分は継ぎ目の診断指標であり、クリック音の知覚評価そのものではない。

目標PPG・初期トークン列・F0等は事前抽出済みで、入力側のストリーミング化は対象外。
予測と実際の出力には同じSPARC合成器を使い、外部の音響変動は与えない。
PPG補正のゲイン等は固定した初期設定で、検証データで調整した値ではない。
一括局所探索（既存のλ=0.03）も参考として掲載するが、総候補評価回数が異なるため上限とはみなさない。

`index.html` に音声比較・集計図、`summary.csv` と `aggregates.csv` に数値を保存する。
各発話の `output.wav` は確定サンプル列そのもの、`result.npz` は最終トークン・予測PPG・観測PPG・最終評価PPG・バイアス履歴、
`trace.jsonl` は確定範囲・観測可能範囲・採否・各出力区間と確定済み接頭辞のハッシュを含む。
学習遷移モデル・モデルチェックサム・参考音声のハッシュ・全設定を `manifest.json` 等に保存する。
既存のモデル・トークン・合成音声・比較結果は変更しない。

## 60 msの情報遅延・20 ms更新のFB実験と音声評価

```sh
bash scripts/compare_delayed_ppg.sh \
    --output-dir outputs/jsut_ppg_delay060_step020

uv pip install --python "$HOME/.local/share/sparc/venv/bin/python" \
    -r requirements-audio-metrics.txt
bash scripts/evaluate_generated_audio.sh \
    --experiment-dir outputs/jsut_ppg_delay060_step020
```

現在時刻tから20 msだけを確定し、探索範囲200・400・800 msを比較する。
観測器には出力済み音声のうちt−60 msまでの波形しか渡さず、PPG計算後に時刻だけを切り捨てる方式は使わない。
直近60 msの予測文脈には実際の出力を使わず、発行済みコマンド時点の予測波形を保持して使う。
STFTのreflect paddingには432サンプルを超える入力が必要なので、最初の40 msの波形が利用できるt=100 msから補正を開始する。
PPGを観測した時点で値を固定する。これは非因果PPGモデルを短い接頭辞で使う近似であり、未来の音声を含めた推定値とは異なる。
最終区間のPPG補完は全出力終了後60 ms経過した時点の解析専用処理とし、制御へは戻さない。

各ステップでは現在位置とPPG差の大きい未来1位置を1パス、各16候補で探索し、現在位置を必ず候補に含める。
λ=0.03、10 msクロスフェード、補正ゲイン0.5、log確率バイアス上限±1。
バイアス更新率は100 msあたり0.25を基準に、新しく観測した区間長に合わせる（20 msなら約0.0559）。
FBなし・無編集も同じ情報制限と更新間隔で実行する。
以前の100 ms更新実験とは、情報制限・ステップ幅・探索位置数が異なるため、純粋な遅延だけの比較ではない。

音声評価には指定の `openai/whisper-large-v3`（turboではない）を使用する。
revisionは `06f233fe06e710322aca913c1bc4249a0d71fce1` に固定し、
モデルとprocessorを `.cache/whisper-large-v3/<revision>/` へ取得してからオフラインで読み込む。
例えば既存環境のPythonで `huggingface_hub.snapshot_download` を呼び、
`repo_id="openai/whisper-large-v3"`、上記revision、上記local_dir、
`allow_patterns=["*.json", "*.txt", "*.safetensors", "*.tiktoken", "*.model"]` を指定する。
ローカル形式は共有ファイルシステムがシンボリックリンク非対応の場合にも対応する。

評価対象は各逐次条件と、元音声・元軌道合成・編集前一括合成・一括局所探索の参考音声。

| 指標 | 定義 |
|---|---|
| CER | Whisper large-v3、日本語・文字起こし・greedy。JSUT正解文との文字編集距離／正解文字数 |
| MCD | WORLD CheapTrickスペクトル→SPTK 24次mel-cepstrum、α=0.42、c0除外の標準距離 |
| STOI | 16 kHz・非extended版、元音声との共通サンプル長で計算 |
| F0 RMSE | WORLD DIO＋StoneMask、50〜550 Hz・10 ms、両音声が有声のフレームでHzとcentsを計算 |
| V/UV誤り率 | 全共通フレームでの有声・無声判定の不一致率 |

CERでは両テキストにNFKC・小文字化・句読点等と空白の除去を適用し、漢字・かな・数字表記の同一化はしない。
そのため、正しい発話でもASRと正解文の表記差でCERが増える場合があり、元音声のCERと認識文も併記する。
CER全体値は文字数によるmicro平均。MCDは参照RMSが最大値の−40 dBを上回るフレームで平均する。
音響指標は元音声との共通時刻を使い、DTW・時間ずらし・個別の音量正規化は行わない。
MCD・V/UVは対応フレーム数、F0 RMSEは有声フレームの二乗誤差をプール、STOIは発話ごとに平均する。
これらは主観的な自然さやMOSそのものではない。

`audio_metrics/index.html` に評価表・音声・全認識文、CSVに発話別と条件別の数値、
`manifest.json` にASR設定・revision・入力音声のハッシュ・ライブラリ版を保存する。
元の制御実験レポートからも評価レポートへリンクする。

## 音声Aの調音軌道を音声BのPPGへ向けて制御する実験

```sh
bash scripts/cross_utterance_ppg.sh \
    --output-dir outputs/jsut_ppg_A_to_B \
    --pairs BASIC5000_0053:BASIC5000_0050 \
            BASIC5000_0050:BASIC5000_0066 \
            BASIC5000_0066:BASIC5000_0053 \
    --horizons 200 400 800
bash scripts/evaluate_cross_utterance.sh \
    --experiment-dir outputs/jsut_ppg_A_to_B
```

既存の試聴テスト発話から `A:B` の組を指定する。既定は上記3組。
Aの連続調音軌道・F0・音量を正規化した時間軸上で線形補間し、Bの調音フレーム数へ合わせる。
その後、固定済みの40 ms・128コードVQモデルでAの軌道をトークン化し直す。
離散トークンIDを補間する方法は使わない。話者埋め込みもAのまま固定する。
BのPPGは時間伸縮せず、Bの調音フレーム長に対応する共通区間を使う。
つまり、Bから使う制御目標はPPGと発話長であり、Bの声質・F0・音量まで同じにする実験ではない。

更新20 ms・観測情報は現在の60 ms前まで・λ=0.03を引き継ぎ、
各探索範囲で無編集・予測補正なし・予測補正ありを比較する。
現在位置＋PPG差の大きい未来1位置、各16候補、1パスを各ステップで探索する。
予測補正なしもBのPPGを目標にするので、FB自体の効果は同じ探索範囲の補正有無で比較する。
観測器への波形入力と未観測区間の予測文脈は、前節の60 ms情報制限を守る。

次の比較音声を各ペアで保存する。

- B原音：目標PPGとASRの参照。
- A初期合成：長さを合わせたAの軌道をVQに通し、AのF0・音量・話者で合成。
- Bトークン＋A合成条件：Bのトークン表現で、内容を再現できるかを調べる参考。
- B元軌道＋A合成条件：量子化と探索以外の制約を調べる参考。

Bの元軌道・トークンは比較音声の生成だけに使い、探索初期値や候補提案には使わない。
`pairs/<A>__to__<B>/inputs.npz` に初期値と固定条件を保存し、各条件には出力音声・PPG・編集トークン・探索履歴を保存する。

評価は指定のWhisper large-v3で行い、Bの正解文への `CER(B)` とAの正解文への `CER(A)` を両方保存する。
`CER(A)` の増加だけではBに変換できたとは判断できず、`CER(B)` の低下と認識文を確認する。
MCD・STOI・F0 RMSE・V/UV誤り率の参照はB原音で、A由来の抑揚等との差も含む。
BのPPGとのJSに加え、長さを合わせたAの初期合成PPGとのJSも記録する。
全体CERは各正解文の文字数、PPG差・音響指標は対応フレーム数等で集計する。
`audio_metrics/index.html` に全認識文と指標を、全体の `index.html` にA/Bの正解文と音声比較を掲載する。
